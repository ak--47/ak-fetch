# ak-fetch 2.1.0 — Adversarial Review (PR #3, e6edac3..70cab9a)

Reviewed: 2026-08-09. Branch `release/2.1.0`, 25 commits, range `e6edac3..HEAD`.
Method: full diff read (`/tmp/akf-pr3-review-package.diff`), full source read of every touched lib module, empirical verification on Node 24.x and Node 18.20.8 (via fnm), full test run, coverage run, typecheck, dist rebuild comparison, npm pack audit. Benchmarks NOT re-run (live external API, per constraints).

---

## Verdict: SHIP WITH FIXES

The core engineering is genuinely good — TaskPool is race-free, the undici dispatcher wiring is correct, transform-once is proven by test, the CJS dist is byte-fresh, and 408 tests pass offline in 2.6s with 89.7%/83.0% coverage. But the release as it stands **does not load on any Node 18.x in ESM mode**, which contradicts `engines: >=18.17`, the README, the CHANGELOG, and the spec's own compatibility constraint. That is a one-line fix (verified below). Until it lands, publishing this is shipping a lie to every Node 18 ESM consumer. Three more Important items (failing typecheck, an unresolved memory-benchmark spec gate, and stale CLAUDE.md) should be settled before `npm publish`.

**Finding counts: 1 Critical, 4 Important, 7 Minor.**

## Q1 — Is the external API identical to main (e6edac3)?

**Verdict: YES (qualified).**

Every element of the frozen surface was compared against main:

- **Root exports (ESM):** `git show e6edac3:index.js | grep -n "export"` vs current `index.js:1576-1593` — identical: default `main` plus the same 9 error classes (`AkFetchError`, `NetworkError`, `TimeoutError`, `RateLimitError`, `RetryError`, `ValidationError`, `ConfigurationError`, `StreamError`, `MemoryError`).
- **CJS dist exports:** `node -e "console.log(Object.keys(require('/Users/ak/code/ak-fetch/dist/index.cjs')))"` → `[ 'AkFetchError', 'ConfigurationError', 'MemoryError', 'NetworkError', 'RateLimitError', 'RetryError', 'StreamError', 'TimeoutError', 'ValidationError', 'default' ]` — matches ESM, matches main.
- **Error classes:** `lib/errors.js` unchanged from main (diff shows no hunks). `RetryError` still copies `statusCode`/`body` from `lastError` (`lib/errors.js`, constructor), which is why `retries: 0` callers still see status codes — pre-existing behavior, preserved.
- **BatchRequestConfig:** `types.d.ts` diff contains JSDoc-only changes (batchSize-0 wording, maxTasks backpressure note, `verbose` `@default true` → `false`, retries wording). No field added, removed, renamed, or retyped. `Result` interface untouched.
- **CLI flags:** flag-by-flag diff of `cli.js` vs main — only delta is `batch_size` default `2 → 1`, which is documented bug fix B15 (library and README always said 1). No flag added or removed. `--version` and `--help` verified working from a foreign CWD (`cd /tmp && node cli.js --version` → `2.1.0`), fixing B8.
- **Behavioral deltas** are confined to the documented-contradiction list the spec licenses (`retries: 0/null`, `batchSize: 0`, `.json` input, multipart, transform-once, CLI default) — with three qualifications:
  1. **`maxTasks` semantics changed beyond the license** (Finding I-4). Old behavior ("queue up to maxTasks, then drain") matched the old docs; the new TaskPool makes `maxTasks` a high-water mark that is effectively inert at the default (`maxTasks: 25 > concurrency: 10` never triggers), and `maxTasks: 0` now means "no backpressure" instead of "constant drain." README/types were re-documented to the new meaning, but the CHANGELOG "Changed" section omits it.
  2. **New export from `cli.js`:** `export const FALLBACK_VERSION = '2.1.0'` — spec says "No new exports." Mitigated: the `exports` map only exposes `"."` and `"./package.json"`, so `ak-fetch/cli.js` is not deep-importable; a test (`dist-cjs.test.js`) pins it to package.json's version. (Finding M-5.)
  3. **The package itself no longer loads on Node 18 ESM** (Finding C-1) — the most consequential "API change" of all: the API is identical, but only on Node ≥19.8/20.

Any agent (or human) following it will run nonexistent commands and reason from a false Node floor.

## Q3 — Do the benchmarks actually show it's faster?

**Verdict: QUALIFIED YES.**

`plans/2.1.0-bench-results.md` read adversarially:

- **Internal consistency:** every percentage delta in the tables recomputes correctly from the raw numbers shown (checked arithmetically). The "Corrections" section is candid about earlier misstatements — a good sign, not a bad one.
- **Direction:** for the throughput-oriented profiles the recorded numbers do show 2.1.0 faster, and the mechanism (keep-alive reuse + continuous pool vs. sawtooth waves) is confirmed independently by the test suite (connection-count and peak-concurrency tests in `test/integration/http-engine.test.js` and `concurrency-continuous.test.js`), so the direction of the claim is credible even if the magnitudes are single-sample.
- **The memory regression is real and is a spec-gate violation:** Minimal Memory profile peak **79.0MB vs 46.4MB (+70%)** with throughput **26,929/s vs 32,174/s (−16%)**. The spec (`plans/2026-08-08-ak-fetch-2.1.0-spec.md:138`) says "no regression tolerated on memory benchmarks." The doc discloses and characterizes it but the gate was never resolved — waived nowhere, fixed nowhere (I-2).
- **Evidence quality is weak:** N=1 run per profile, against a **live external API** (Mixpanel) with uncontrolled ordering effects (2.1.0 was run before main), raw JSON result files are gitignored, and the main-branch comparison worktree was deleted — so no number in the doc is independently verifiable from the repo. Section-1 claims like "peak memory: main 48–92MB, 2.1.0 64–85MB" have no supporting table at all (M-6).

Net: "faster on throughput" is believable and directionally corroborated; "no memory regression" is false by the project's own stated bar.

## Q4 — Are all files properly linked in package.json?

**Verdict: QUALIFIED YES.**

- **npm pack contents** (17 files, 80.6 kB): LICENSE, README.md, cli.js, dist/index.cjs, index.js, all 10 lib/*.js, package.json, types.d.ts. Everything referenced by `main`/`module`/`exports`/`types`/`bin` is present and resolves. `CHANGELOG.md` is NOT shipped (not in `files`, not auto-included by modern npm) — for a release whose migration story lives in the changelog, that's worth a thought (M-6-adjacent, noted in table as part of M-4 docs polish; repo copy remains available).
- **Dependencies vs imports:** `grep -rhoE "from '[a-z@][^']*'" index.js cli.js lib/ | sort -u` → exactly `ak-tools`, `dayjs`, `dotenv`, `murmurhash`, `tough-cookie`, `undici`, `yargs` (+ node builtins). - **dist freshness:** `npm run build` produces a byte-identical `dist/index.cjs` (verified twice — once directly, once via `npm pack`'s `prepare` hook leaving the tree clean). CJS dist loads and `dryRun`s correctly on Node 18.20.8 (esbuild emits `import_fs2.openAsBlob` property access, which tolerates the missing export — the ESM source does not).
- **prepare script** rebuilds dist on publish — good guard against stale dist.

### Explicitly cleared (adversarial checks that found nothing)

- **`lib/concurrency.js` TaskPool:** no race, no over-admission (atomic slot handoff — `#release` transfers the slot to a waiter without decrementing `active`), no unhandled rejections (task bodies own try/catch; pool wraps anyway), no livelock, `drain()` correct via settled-promise loop. `task-pool.test.js` even registers an unhandled-rejection listener.
- **Transform-once (A1):** `addBatchToQueue` builds `requestConfig` with `transform: undefined, clone: false`; `transform-once.test.js` proves single application with a non-idempotent transform.
- **`enableConnectionPooling`:** not ignored — `createHttpClient` (`index.js:1080-1104`) maps it to `keepAlive: config.enableConnectionPooling ? config.keepAlive : false` → `pipelining: 0` when off. Connection-count tests prove reuse on / off.
- **Timeout instant-abort (B5):** killed — `effectiveTimeout = timeout ?? this.options.timeout` inside `executeRequest` (`http-client.js:146`).
- **429 body consumption (B3), multi-Set-Cookie (B2, runtime feature-checked `getSetCookie`), case-insensitive headers (B4), multipart boundary round-trip (A5):** all fixed and covered by real-request tests.
- **CJS dist:** byte-identical on rebuild, exports match ESM, loads and runs on Node 18.20.8 and 24.
- **batchSize edges:** `0 → Infinity → single request` (matches docs, tested); `1` default consistent everywhere now.
