## Key Findings

### Performance Highlights

1. **Connection pooling delivers +52% throughput improvement** - Critical feature now functional in 2.1.0 (was a no-op in 2.0.16 per finding B1)

2. **Optimal balanced config:** concurrency 15, batch 2000 achieves **~10,500 records/sec** with 100% success rate

3. **Memory efficiency:** Handles 100k records in **~41MB peak memory** (0.42KB/record) with proper configuration

4. **Continuous concurrency (fix C1):** Smooth throughput without the wave-based sawtooth pattern

5. **Retry semantics (fixes A3/A4):** Fire-and-forget mode (`retries: null`) correctly performs single attempt with no retries

### Comparison Limitation

Unable to provide main branch (2.0.16) vs 2.1.0 direct comparison due to:
- Git worktree environment variable isolation preventing MIXPANEL_AUTH propagation
- Main branch benchmarks require real Mixpanel API access (no local mode available)

**Expected improvements based on fixes (not empirically validated):**
- Connection pooling: +52% throughput (measured in 2.1.0, was 0% in 2.0.16 where pooling was a no-op)
- Continuous concurrency: Smoother sustained throughput vs wave pattern
- Transform efficiency: 2x reduction in transform overhead (applied once instead of twice)
